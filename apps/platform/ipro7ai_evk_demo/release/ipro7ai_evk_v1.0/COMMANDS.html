Command Reference IPRO7AI EVK

Every peripheral, one shell

The board exposes a single command shell, and every way in reaches the same one. That is why there is no separate API per peripheral, and why a command added to the firmware shows up everywhere at once.

Serial

/dev/cu.usbserial-* at 115200. Always available, needs a cable.

Android

EVK Bench, over BLE. Buttons for the common commands plus a console.

Terminal

tools/evk.py over BLE. -f file replays a whole test run.

Browser

Web Bluetooth panel. Chrome or Edge, top-level tab.

The radio comes up on its own at boot, so the wireless clients have something to connect to without a cable first. It takes a little over ten seconds — RF calibration and the 32 kHz qualification — and announces itself in the log when it is ready.

Bluetooth

bt link, LE Audio, RF calibration
bt statusLink state, address, LE Audio stream state.
bt rfCheck this first when anything streams badly. Calibration status for this boot; roscal must read 3.
bt audioStream state, decode counters, measured DAC drain rate, peak level.
bt initBring up controller and host by hand. Only needed if the boot-time start failed.
bt adv on|offConnectable advertising.
bt name <string>Advertised name, applied at the next advertising start.
bt disconnectDrop the current link. The firmware allows one at a time.
bt rate <16|24|32|48|0>Publish only this LC3 rate; 0 restores all. At 16 kHz the decoder upsamples internally, so the anti-alias filter and rate matcher drop out of the path entirely — that is how you rule the DSP out.
bt vol <0-255>Drive the volume locally, to tell a silent phone slider from a dead volume path.
bt dacrate [hz]Override the assumed DAC rate; 0 returns to automatic.
bt capture <sec>Capture decoded PCM into PSRAM, then mic play replays it through the DAC path a tone already proves clean.

Why bt rf comes first. An uncalibrated receiver does not report an error — it drops packets, and the resulting audio imitates every other fault in the chain. Loss measured on this board ran from 1.2 % to 30 % depending on nothing but whether that calibration converged.

Video player

vid clips from the card, panel and DAC
vid play <n>Load <n>.ipv from the card root into PSRAM, then play it.
vid stopStop the current clip.
vid statusGeometry, frames shown, achieved rate, and the blit time against the frame slot.
vid auto on|offWatch the card slot; insertion mounts and plays.
vid loop on|offKeep replaying the list while the card stays in.
vid memLargest block the heap will actually hand out, and the clip length that allows.

Play the largest clip first. The payload buffer is claimed once and never resized, so whichever clip loads first fixes the reservation for the whole session. Start small and every larger clip fails — with 8 MB of heap free, because the free space is not contiguous. Pack clips with tools/mkvid.py and keep them under about 6 MiB.

Speaker

spk on-chip DAC into the class-D amplifier
spk statusState, gains, level meter.
spk tone [Hz] [sec] [amp%]Synthesised sine. Defaults to 1000 Hz, 2 s, 30 %.
spk gain <-20..48>Software make-up gain applied before the DAC.
spk on | spk offAmplifier enable. Active high on this board.
spk dc <0..1023>Hold a DC code for multimeter checks. Leaves the amplifier off deliberately.
spk stopStop whatever is running.

A tone is the cleanest reference you have. It shares the converter, amplifier and analogue path with everything else but involves no decoder, no radio and no resampling. Clean tone with rough streamed audio puts the fault upstream of the DAC, and that one observation removes most of the chain from suspicion.

Microphone

mic PDM capture on GPIO18/19
mic rec [sec]Record into PSRAM. Default 3 s, maximum 10.
mic play [gain_dB|auto]Play the recording; auto picks a gain from the take's own peak.
mic status Same view as spk status.
mic gain <0..18>AUADC digital gain, applied at the next capture start.
mic loop [sec]Live PDM to DAC. It will howl if the speaker can reach the microphone.
mic scope [sec]Scrolling waveform on the panel.
mic probeClock the pins by hand and watch DATA — separates dead wiring from a silent capture path.
mic pads [hex]Dump the GLB and HBN pad registers for GPIO18/19, or write a value to sweep them.
mic dump [off] [n]Print recorded samples — tells "no frames arrived" from "frames arrived and every sample is zero".
mic ch <left|right>PDM slot. Settable only before the first capture.

Pad ownership is split across two registers. The AON bits live in both HBN_PAD_CTRL_0 and HBN_PAD_CTRL_2, so reading only the first reports the pins as free while the input buffer is still switched off and the microphone records silence. mic pads shows both.

Camera

cam SC101IOT over DVP, ISP to the panel
cam probeSCCB, MCLK, reset and sensor probe without streaming.
cam startStart the ISP pipeline and live preview.
cam stopStop the preview and park the sensor in reset.
cam statusProbe state, geometry, frame and error counters.
cam fps <1..30>Preview rate target, applied live.
cam rot <0..3>Panel orientation; 1 and 3 are landscape.
cam fit <box|crop>How a 16:9 sensor lands on a 4:3 panel.
cam order <rgb|bgr>Which channel is byte 0 of an ISP pixel. Fixes swapped red and blue.
cam pixels [n]Dump raw ARGB words from the newest frame.
cam rst <0|1>Drive the sensor reset line directly; 0 asserts.

Zero frames and zero errors means no pixel data arrives at all — not corrupted data, none. If SCCB still answers, the sensor has power and I²C works, so look at the DVP side. MCLK shares GPIO41 with the boot strap, so a jumper left on J6 silences the sensor clock while I²C carries on regardless.

SD card

sd SDH in 4-bit mode, FatFS at sd:
sd mountRegister the driver and mount. Prints the full card identification.
sd statusCard detect, mount state, free space.
sd ls [path]Directory listing. Defaults to sd:/.
sd bench [path]Read a file straight through with nothing else running, and report the rate.
sd unmountUnmount.
sd testWrite a small file and read it back.
sd power <on|off>Supply gate. Polarity is unconfirmed on this board.

The volume prefix is not optional. Paths are sd:/name; a bare filename goes to drive 0, which has no work area and returns FR_NOT_ENABLED rather than "file not found". sd bench exists to separate a card that cannot sustain a rate from one that only fails while the panel is also being driven — the second is what actually happened here, and the first is what it looked like.

Panel

lcd ST7789P3, 240×320, SPI
lcd statusCurrent state.
lcd init [minimal|tuned] [noclear]Re-run an initialisation sequence.
lcd bars | rgbtest | checker | grad | gray | rulerTest patterns.
lcd dir <0..3> [mirror]0 and 2 portrait 240×320; 1 and 3 landscape 320×240.
lcd bl <on|off>Backlight enable on GPIO12.
lcd inv <on|off>Inversion. An IPS normally-black panel needs this on.
lcd bgr <on|off>MADCTL colour order, for swapped red and blue.
lcd clk <hz>SPI clock. At or below 16 M uses XCLK, above that BCLK.
lcd fill <colour>Solid fill. Names: black white red green blue yellow cyan magenta gray.
lcd box <x0> <y0> <x1> <y1> <colour>Filled rectangle.
lcd benchTime one full-screen fill.
lcd idRead the identification registers back over SDA.
lcd cmd <hex> [p0 p1 …]Raw register write.
lcd read <hex> <nbytes>Raw register read, 1 to 8 bytes.

The bus is the ceiling for anything animated. A full 320×240 frame at 16 bits is 1.23 Mbit, so at 16 MHz it cannot be sent in less than about 77 ms — roughly 13 fps before anything else is counted. lcd bench measures it on the actual board.

Supply

vbat · adc · vbus GPADC
vbatThe SoC's internal supply tap.
adc <ch> [ratio_x100]Read a GPADC channel. The ratio scales back up through an external divider — two equal resistors is 200.
vbusIs the USB-C connector powered? Read from the USB transceiver's comparator, not a GPIO.
vbus skipRelease a build that is holding its start-up until the cable goes in.

The firmware cannot see the battery. The charger's status outputs drive LEDs and reach no GPIO, and the cell never meets an ADC pin. The channel named "VBAT/2" is an on-die tap of the SoC's own supply, which here is the 3V3 rail out of the buck-boost — not the cell. Measuring the cell needs a divider fitted into one of channels 0–11.

What vbus answers, and what it doesn't. It reports that the connector has 5 V on it — any source, an enumerated host or a dumb charger — because it watches the rail, not the data lines. It is not charge state. It is also only interesting with a cell fitted: the SoC sits downstream of VBAT, so on a board with no battery VBUS is already true by the time any code runs, and plugging the cable is the power-on event.

Where to start

order when audio or streaming is wrong

Check the receiver was calibrated

bt rf — roscal must read 3. It fails silently and the packet loss that follows imitates every other fault, so everything below is unreliable until this passes.

Prove the analogue path with a tone

spk tone 1000 2 30 — no decoder, no radio, no resampling. Clean here means the converter, amplifier and speaker are all fine and the fault is upstream.

Take the DSP out of the path

bt rate 16, then reconnect. At 16 kHz the decoder upsamples internally, so no anti-alias filter runs and the rate matcher sits at unity. Still wrong at 16 kHz means the conversion was never the problem.

Separate delivery from decoding

bt capture 5 during a stream, then mic play. A clean replay says the decoder output was always right and the fault is in real-time delivery; a rough one puts it before the DAC.

Read the loss, not the symptom

bt audio — concealed frames are counted separately from decoder rejections, because a link problem and a payload problem need opposite investigations.

Nothing matches that. Try a peripheral name, or part of a command.
Commands come from the firmware's own usage text. Anything added to the shell works from every client without a change to any of them — they all write to the same place.
