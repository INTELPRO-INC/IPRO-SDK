# 一、硬體接線

## 1.1 面板 FPC 50-pin 完整分類

連接器：**Hirose FH34SRJ-50S-0.5SH**（50 pin，0.5 mm 間距）

### A. 接到 MCU 的訊號（6 支）

| FPC Pin | 訊號 | 方向 | 說明 | 本包預設 GPIO |
|---|---|---|---|---|
| 28 | RST_N | MCU → 面板 | 重置，**低有效** | GPIO11 |
| 29 | BUSY_N | 面板 → MCU | 忙碌狀態，**低=忙碌** | GPIO10 |
| 30 | DC | MCU → 面板 | 資料/命令；**3-wire 模式不使用** | GPIO12 |
| 31 | CSB | MCU → 面板 | 晶片選擇，低有效 | GPIO17 |
| 32 | SCL | MCU → 面板 | 序列時脈 | **GPIO15**（硬體 SPI/PIO 需要，不可調） |
| 33 | SI0 | **雙向** | 序列資料；讀取時需回讀 | **GPIO13**（硬體 SPI/PIO 需要，不可調） |
| — | PWR | MCU → 板 | 升壓電路（VGH/VGL/VSH/VSL）電源開關，**非面板本身訊號** | GPIO14 |

全部集中在 **GPIO10~17** 這個區塊，GPIO16 空著沒用到（見下方）。

> **腳位不能任意調換**：SoC 由腳位編號 **modulo 4** 決定 SPI 訊號角色，與選哪個
> SPI 實例無關：
> ```
> n % 4 == 0 -> MISO      n % 4 == 2 -> SS
> n % 4 == 1 -> MOSI      n % 4 == 3 -> SCLK
> ```
> 在 GPIO10~17 這個區塊內，扣掉已佔用的 RST(11)/DC(12)/CS(17)/BUSY(10)/PWR(14)，
> 剩下 13、15、16 三支：13→MOSI、15→SCLK、16→MISO。SI0 是單線雙向，
> 不需要獨立的 MISO，所以 **SCL 固定在 GPIO15、SI0 固定在 GPIO13，GPIO16 空著**。
> CSB、DC、RST_N、BUSY_N、PWR 沒有這個限制，是純 GPIO。
>
> ⚠️ **矽片已知限制**：SPI0 的 TX DMA 交握在 **8 MHz 以上不可靠**
> （與 GH7007 SPI LCD bring-up 遇到的同一顆矽片行為一致）。若貴司韌體用
> DMA 餵 SPI0 且時脈設在 8 MHz 以上，這可能是不穩定的來源之一，
> 建議先試著把時脈降到 8 MHz 以下、或改走輪詢方式送資料排除。

> ⚠️ **SI0 必須雙向。** 版本暫存器讀取（`epd_rev`）需要面板回驅此線。
> 若線路上有單向緩衝器、電平轉換器或阻擋回讀方向的元件，寫入看似正常，
> 但永遠讀不到值。

# 二、SPI 設定

## 2.1 本包採 GPIO 軟體模擬，不使用 SPI 週邊

與元太原廠參考韌體相同做法。理由：

- **除錯時少一組變數。** 面板是否會動作尚未確認，此時若同時引入 SPI 週邊的
  時脈、極性、位元組寬度設定，出錯時無法區分是接線問題還是 SPI 設定問題。
- **3-wire 是 9 bit 框架**，一般硬體 SPI 週邊不支援；原廠範例即採軟體模擬。

面板確認可動作後，4-wire 模式可改用硬體 SPI 加速大量資料傳輸（120 KB）。

時序快慢由 `src/epd_el036.h` 的 `EPD_SPI_DELAY_LOOPS` 調整（預設 4）。
面板接在長線或未端接的排線上時可調大。

## 2.3 SPI 模式

| 項目 | 設定 |
|---|---|
| 極性 CPOL | **0** — SCL 閒置為低電位 |
| 相位 CPHA | **0** — 資料於 SCL **上升緣**被取樣 |
| 對應 | **SPI Mode 0** |
| 位元順序 | **MSB first** |
| CSB | 低有效 |

資料在 SCL 為低電位時變化，上升緣鎖存。閒置狀態：`SCL=L, SDA=H, CSB=H, RST_N=H`。

## 2.4 兩種匯流排模式的框架差異

### 3-wire（9 bit）— 面板預設

D/C 旗標作為**第 9 個位元**併入資料流，DC 腳不使用。

```
CSB  ‾‾\____________________________________/‾‾
SCL  ____╱‾╲_╱‾╲_╱‾╲_ ... _╱‾╲______________
SDA  ──<D/C><D7><D6> ...  <D0>───────────────
         ↑
      0=命令  1=資料
```

### 4-wire（8 bit）

D/C 是獨立線路，在整個位元組期間維持電位。

```
CSB  ‾‾\____________________________________/‾‾
DC   ──<─── 0=命令 / 1=資料，全程維持 ───>──────
SCL  ____╱‾╲_╱‾╲_ ... _╱‾╲__________________
SDA  ──<D7><D6> ...  <D0>───────────────────
```

**本包每個位元組都是獨立的 CSB 週期**（CSB 拉低 → 傳送 → 拉高），
與原廠參考韌體一致。

> 註：Application Note 第 5 頁記載「讀取時 CSB 必須全程維持低電位」，
> 與原廠韌體實際的逐位元組切換不一致。本包依原廠**實際程式碼**實作。
> 若讀取異常，這是第一個可嘗試改為另一種做法的地方。

## 2.5 讀取操作的特殊框架

版本暫存器讀取（`epd_rev`）的每個位元組：

1. CSB 拉低
2. 送出 **D/C = 1**（與資料位元組相同）—— 3-wire 為 1 個時脈，4-wire 為拉高 DC
3. SDA 切換為輸入
4. 讀 8 個位元（於 SCL 高電位期間取樣）
5. SDA 切回輸出並拉低
6. CSB 拉高

**步驟 2 的前導 D/C 位元不可省略**，省略則面板不會回驅任何資料 ——
症狀與接線錯誤完全相同，難以區分。

## 2.6 PIO 引擎（3-wire 原生，建議路線）

IPRO7 內建 RP2040 風格的 PIO（2 個狀態機、32 格指令記憶體、side-set、autopull、
DMA DREQ）。它是**唯一能同時滿足這片面板三項需求**的引擎：

| 需求 | 軟體模擬 | 硬體 SPI | **PIO** |
|---|---|---|---|
| 3-wire 9 位元框 | ✅ | ❌ 只有 8/16/24/32 | ✅ 迴圈計數決定 |
| 逐位元組 CSB | ✅ | ⚠ CPU 手動，約 20 µs/位元組 | ✅ 寫在程式裡，零成本 |
| 整屏不佔 CPU | ❌ | ❌ | ✅ **DMA 餵 FIFO** |
| 整屏 120000 位元組 | 約 2.5 s | 約 2.4 s | **約 0.32 s** |

```
epd_bus 3           PIO 只在 3-wire 有效（面板預設就是 3-wire）
epd_engine pio      切換引擎
epd_engine          查詢目前引擎與實際 SCL 頻率
epd_engine bitbang  切回參考實作
```

### 程式本體（5 條指令）

```
 0: pull block                 等待資料 -- 此時 CSB 仍是高
 1: set  pins, 0    side 0     CSB 低、SCL 低          -- 框架開始
 2: set  x, 8                  9 個位元
 3: out  pins, 1    side 0     送出一位元，SCL 低
 4: jmp  x--, 3     side 1     SCL 高 -- 面板在此取樣
 5: set  pins, 1    side 0     CSB 高                  -- 框架結束
    (wrap 5 -> 0)
```

**等資料一定要放在拉低 CSB 之前。** 先開框架再讓 autopull 停在字中間，
狀態機會停在 `out` 而 CSB 已經是低的 —— FIFO 空多久就停多久，也就是每送完一個
命令、每次傳輸結束之後。面板會看到 CSB 一直被選取，逐位元組框架完全失效。
（實測波形上就是 CSB 掉下去之後再也沒回來。）所以 autopull 關閉、改用明確的
`pull`；`pull` 會整個覆寫 OSR，前一個字用剩的 23 個位元自然被丟掉。

`jmp x--` 是先判斷再遞減，所以 `x = 8` 會執行九次：一個 D/C 位元加八個資料位元。

腳位分組：`out` = SDA、side-set = SCL、`set` = CSB。**PIO 沒有硬體 SPI 那個
「腳位編號 modulo 4」的限制**，三支腳可以任意擺放。

### 時序

每位元組 22 個週期（pull 1、框架前後各 1、位元 18、CSB 高 1）。PIO 基頻 96 MHz，
每位元 2 條指令，所以 clkdiv 以兩倍 SCL 為目標；4 MHz 時 clkdiv = 12，
指令速率 8 MHz，每位元組 2.6 µs。

CSB 拉高只持續 1 個週期就 wrap 回去開下一個框 —— 在 8 MHz 下是 125 ns，
規格要求 tCHW 最小 40 ns（Application Note Table 3），有裕度。

### 資料如何送

autopull 門檻設 9，**一個 32 位元字裝一個 9 位元框**（放在最高的 9 個位元）。
把框連續打包會省 3.5 倍記憶體，但需要事先把 120000 位元組全部打包成 135 KB —— 
這個無 PSRAM 的組態擠不出來。4 MHz 下狀態機每 2.6 µs 才吃一個字，
1.5 MB/s 的 DMA 流量不值得為此增加複雜度。

DMA 緩衝區 4 KB，放在 `.nocache_ram`（OCRAM 的未快取別名），
linker 已把堆積起點推到其後，不會重疊。

### 實機驗證結果（2026-08-19）

以邏輯分析儀量測，**PIO 引擎全部通過**：

| 項目 | 實測 |
|---|---|
| SCL 頻率 | **4 MHz**（週期 250 ns、脈寬 125 ns、空佔比 50%） |
| 每框時脈數 | 9 拍 |
| CSB 框架 | 傳輸期間低、框間高 |
| 命令位元組 | `0x070`（REV）、`0x010`（DTM）— D/C 位元為 0 ✓ |
| 資料位元組 | `0x111` — D/C 位元為 1、內容 `0x11` ✓ |
| 整屏 | **120011 筆解碼**（120000 資料框 + 命令）|
| 整屏耗時 | **417 ms**（CPU 餵 FIFO）|

整屏耗時對照：bit-bang 2.5 s → PIO **417 ms**（快 6 倍）。理論下限是狀態機的
330 ms（每框 22 週期 @ 8 MHz 指令速率），剩下 87 ms 是 CPU 迴圈開銷。

> **DMA 在本平台未能運作**，驅動會自動回退成 CPU 餵 FIFO 並印出訊息。
> 症狀是通道武裝後 busy 位元永不清除（PIO 的 TX 請求沒送達 DMA）。
> 沒有繼續追查：面板本身的六色刷新要數十秒，而 DMA 最多只能再省 87 ms。
> **波形時序兩條路完全相同**（節奏由狀態機決定），只有 CPU 負載有別。
>
> 餵資料的緩衝區 `s_chunk` 放在 `.nocache_ram` 是 DMA 的一致性需求；
> CPU 路徑刻意不讀它 —— 每個字從未快取記憶體讀回來的代價遠高於
> `pio_sm_put()` 本身，實測差距是 856 ms 對 417 ms。

> 預設仍是軟體模擬。本包的用途是先確認面板點不點得亮，而軟體模擬是逐行對照
> 元太參考韌體的實作，出問題時才排除得掉驅動本身的嫌疑。面板確認正常後
> 再切 `epd_engine pio`。

> **PIO 需要的三個前置步驟**（`epd_pio.c` 的 `pio_block_clock_on()`）：
> PIO 區塊開機是被壓在軟體重置裡、時脈閘也是關的，必須先脈衝
> `GLB_SWRST_CFG1.PIO`、開 `GLB_CGEN_CFG0.PIO`、再設 `GLB_CLK_CFG6` 的
> `PIO_CLK_EN`。少做這步的症狀是腳位一 mux 過去就全部歸零並停住 ——
> 在分析儀上看起來像 CSB 被拉低卡死，完全不像週邊沒在跑。

### 時脈掃描與預設值選擇（2026-08-19，`epd_pio_hz` 免重燒調整）

用 `epd_pio_hz <Hz>` 在無面板狀態下實測掃過幾個頻率：

| 頻率 | 結果 |
|---|---|
| 4 MHz | 乾淨（第一個驗證通過的值，見上表） |
| **8 MHz** | 乾淨 — **選為預設值** |
| 12 MHz | **每次都不穩**，重現性 100% |
| 16 MHz | 乾淨 |

**12 MHz 兩側乾淨、唯獨它不穩，不像是韌體計時問題**（那種問題通常隨頻率單調
變差，越快越糟，不會中間單獨凹一個洞）。12 MHz 與 16 MHz 的 CLKDIV 都驗算過
是乾淨整數、無小數餘數（12 MHz → 4+0/256、16 MHz → 3+0/256），狀態機內部
理論上不該有時基抖動。

比較可能的原因是**開路飛線的駐波反射** —— 手邊沒有面板，GPIO28-33 這幾條線
全是開路的飛線，末端反射係數接近 1，在特定波長會與原始邊沿疊加成跨越邏輯
閾值的假邊沿。這種效應天生就是非單調的、跟飛線長度相關，換成面板的短
FPC 排線（阻抗較受控）不一定會重現。

**因此 `EPD_PIO_HZ` 預設值只是「無面板飛線下量得乾淨」，不是一個經過完整
驗證的上限。** 面板實際接上後建議重新掃一次，`epd_pio_hz` 這個指令本身沒有
拿掉，就是留給那時候用的。

程式本身的零裕度上限約 16.7 MHz（tSDS/tSDH ≥ 30 ns，Application Note
Table 3），細節見 `epd_el036.c` 的 `epd_set_pio_hz()` 註解。

## 2.6 硬體 SPI（4 MHz）

預設已啟用（`EPD_HW_SPI_ENABLE 1`、`EPD_HW_SPI_HZ 4000000`），但**只在 4-wire 模式生效**。

```
epd_bus 4         切到 4-wire
epd_spi 1         啟用硬體 SPI（預設就是 1）
epd_spi 0         切回軟體模擬
```

### 讀取一律走軟體模擬

即使在 4-wire + 硬體 SPI 模式下，**讀取仍然是 bit-bang**。SI0 是單線雙向，
讀取時必須在傳輸中途把腳位轉成輸入，控制器做不到這件事。

驅動會在讀取前把 SCL/SDA 的 mux 交還給 GPIO、讀完後由下一次寫入自動重新接管。
這一步不能省 —— 腳位還掛在 SPI 週邊時，對它們呼叫 `gpio_write()` **完全無效**，
時脈不會動，讀回來的值是垃圾，而且看起來就像面板沒回應。

### 為什麼 3-wire 不能用硬體 SPI

控制器的框架寬度只有 8 / 16 / 24 / 32 位元（`SPI_FrameSize_Type`），**沒有 9 位元**。
而 3-wire 每個位元組都要在前面多送一個 D/C 位元。

也不能把 9 位元流打包成連續的 8 位元框送出 —— 面板要求**每個位元組都要獨立的 CSB
週期**（元太參考碼 `SPI_DATA()` 就是這樣寫的），打包會讓 CSB 停在低電位橫跨整段。

所以 3-wire 一律走軟體模擬，這是硬體限制不是實作選擇。

### 腳位不能任意換

SoC 由 **腳位編號 modulo 4** 決定 SPI 訊號角色，與選哪個 SPI 實例（AF 值）無關：

| `n % 4` | 角色 |
|---|---|
| 0 | MISO |
| 1 | MOSI |
| 2 | SS |
| 3 | SCLK |

依據 `bsp/board/ipro7/ipro7_dual_imu_board_config.h`：GPIO37 AF=4 是 SPI0_MOSI（37%4=1）、
GPIO39 AF=4 是 SPI0_SCLK（39%4=3）、GPIO31 AF=26 是 SPI1_SCLK（31%4=3）、
GPIO33 AF=26 是 SPI1_MOSI（33%4=1）。

同一個規則套在目前的 GPIO10-17 接線：SCL 固定在 GPIO15、SDA 固定在 GPIO13
（見第一章接線表）。換一組腳位時都要重新用這條規則反推，不要沿用舊配置的
數字——GPIO28-33 那組合是內建 flash 組態下的另一種可行排法（SCL=31、SDA=29），
兩組排法都合法，但不能混用。

CSB 維持軟體控制（`ignore_cs = 1`），因為面板要求逐位元組切換，硬體晶片選擇做不到。

### 重點：拉高時脈不會自動讓刷新變快

每個位元組獨立 CSB 框的成本約 **20 µs**（CSB 切換 + `spi_transmit` 呼叫開銷），
在 120000 位元組下完全蓋過時脈本身：

| 方式 | 整屏資料耗時 |
|---|---|
| 軟體模擬 450 kHz | 約 2.5 秒 |
| 硬體 4 MHz、**逐位元組 CSB** | 約 2.4 秒 ← **幾乎沒改善** |
| 硬體 4 MHz、**連續叢集** | 約 0.24 秒 |

要真的變快必須讓 CSB 保持拉低、整段串流送出，這就是 `epd_burst`：

```
epd_bus 4
epd_spi 1
epd_burst 1       整屏資料改為連續叢集（每 256 位元組一次 CSB）
```

> ⚠ **`epd_burst` 預設關閉，且尚未用真實面板驗證。**
> 元太參考韌體 `SPI_DATA()` 是**每個位元組都切 CSB**；Application Note 只規定
> 讀取時 CSB 要全程拉低，寫入沒有明講。若刷新結果錯誤或全白，
> **先把 `epd_burst` 關掉**再懷疑其他地方。

`epd_rev`、`epd_init` 的命令與參數一律維持逐位元組框架，不受此選項影響 ——
只有整屏影像資料會走叢集。

### 速度與注意事項

| 項目 | 值 |
|---|---|
| 面板寫入上限 | 20 MHz（App Note Table 3） |
| 面板讀取上限 | 6.67 MHz |
| 原廠建議 | 5 MHz |
| 本包預設 | **4 MHz** |
| 軟體模擬實測 | 約 385 kHz |

120000 位元組的整屏資料：軟體模擬約需 2.5 秒，4 MHz 約 0.24 秒。

> ⚠ **兩個已知的矽片行為**，4 MHz 都不會踩到，但改快之前要知道：
> - SPI0 的 TX DMA 交握在 **8 MHz 以上**不可靠。
> - 時脈除頻器是**向下取整**，請求值和實際跑的速率可能不同 —— 請用邏輯分析儀量，不要假設。

## 2.7 用邏輯分析儀驗證（無面板也可做）

沒有面板時 BUSY_N 浮空讀為低（=忙碌），所有流程都會在送出任何 SPI 邊緣之前中止，
匯流排上抓不到東西。用 `epd_nobusy` 略過等待即可抓波形：

```
epd_nobusy 1      關閉 BUSY_N 等待
epd_rev           送出 REV 命令 + 3 次讀取
epd_nobusy 0      接上面板後務必關回
```

> ⚠ 接上真實面板後一定要設回 0。忽略 BUSY 去寫入，正是這條訊號存在的目的所要防止的事。

### 分析儀設定

| 欄位 | 設定值 |
|---|---|
| SCS | GPIO17（CSB） |
| SCLK | GPIO15（SCL） |
| MOSI | GPIO13（SDA / SI0） |
| MISO | GPIO13（**同一支腳，雙向**）；工具不允許重複時選「無」 |
| 位元順序 | MSB 在前 |
| 每次傳輸位元數 | **3-wire = 9**、4-wire = 8 |
| CPOL | **0**（閒置低） |
| CPHA | **0**（前緣取樣） |
| Enable | 低態有效 |

CPOL/CPHA 都是 0，也就是 **SPI Mode 0**。設成 Mode 3 會解不出資料。

**位元數設 9 是關鍵**：3-wire 沒有 DC 腳，命令/資料靠每個位元組前多送一個位元區分。
設成 8 的話每個位元組都會錯一位，看起來像韌體壞掉，其實只是解碼器設定不對。

### 實測結果（本包已驗證）

執行 `epd_rev` 抓到的 9-bit 解碼：

```
0x070   0 + 0x70   ← 命令 REV
0x180   1 + 0x80   ← 讀取（無面板，SDA 浮空）
0x180   1 + 0x80
0x1C0   1 + 0xC0
```

第一筆 `0x070` 最高位為 0 = 命令、內容 `0x70` = REV，**與程式碼完全一致**。

後三筆不是面板回應。讀取時韌體會把 SDA 轉成輸入，沒有面板時線上沒人驅動，
分析儀量到的是殘留電荷衰減的波形（第一個位元讀到高、之後掉為低），
所以呈現 `0x80` / `0xC0` 這種形狀。**接上面板後這三個值才有意義。**

CSB 每個位元組獨立拉低再拉高，與原廠 `SPI_GET_DATA()` 的框架一致 —— 這點很重要，
多位元組讀取時若整段共用一次 CSB，面板不會正確回應。

# 四、驗證順序

## 步驟 1：`epd_rev` ← 一定要先做這個

```
epd_rev
```

讀取版本暫存器（REV, 0x70）。這是**純讀回操作**，不需要影像、不需要
波形檔、不需要高壓電源軌，但它要成功必須同時滿足：接線正確、匯流排
模式正確、reset 時序正確、BUSY 訊號正常。

| 結果 | 判讀 |
|---|---|
| 讀到合理值（非 0x00 / 0xFF） | ✅ **介面正常**，可繼續步驟 2 |
| 讀到 `0x00` 或 `0xFF` | ❌ 介面不通，見第五節 |
| `BUSY never went high` | ❌ BUSY_N 卡在低電位或未接，或面板無 VDD |

**讀不到就不要往下做** —— 介面不通的情況下，顯示流程不可能成功。

## 步驟 2：`epd_init`

```
epd_init
```

執行雙重 reset 與完整暫存器序列。

> **Reset 是雙重的**（Application Note Figure 10）：
> `VDD on → 20 ms → RST_N 低 ≥30 ms → 高 ≥30 ms → 低 ≥30 ms → 高`
> 僅執行單次 reset 會導致初始化不完全，且後續命令會被靜默忽略。

## 步驟 3：顯示

```
epd_white     epd_black     epd_red
epd_yellow    epd_blue      epd_green
epd_cycle                   # 依序跑完六色
```

**單次刷新需數十秒**，這是 Spectra 6 的正常特性，不是當機。指令會顯示實際耗時。

# 五、`epd_rev` 讀不到時的排查

## 1. 匯流排模式（最可能）

面板**預設 3-wire 9-bit**（BS0 = High）。若板子按 4-wire 接線，
**BS0 必須主動拉低**。

不需重燒即可切換測試：

```
epd_bus 4
epd_rev
```

兩種模式都試過仍失敗，再往下查。

## 2. SI0 雙向性

REV 是讀回操作，SI0 必須能雙向。檢查該線上是否有單向緩衝器、
電平轉換器或阻擋回讀方向的元件。

## 3. 接線

SCL / SDA / CSB 是否對調；CSB 是否確實到達面板；RST_N 是否可被 MCU 控制。

## 4. BUSY_N

若回報 `BUSY never went high`：確認 pin 29 已接、面板 VDD 正常。
BUSY_N 為**低電位表示忙碌**。

# 六、`epd_rev` 通過但顯示失敗

介面已確認正常，此時問題在電源軌或波形。請量測 FPC：

| 腳位 | 規格值 |
|---|---|
| VGH (49) | +20 V |
| VGL (13) | −20 V |
| **VSH (15)** | **+15 V** |
| VSL (18) | −15 V |

> ⚠️ **量測時機很重要。** 各軌電壓由 `BTST1` / `BTST2` / `BTST3` 三組暫存器
> 控制，並在刷新過程中由**第二次 `BTST2` 寫入**調整。
>
> 因此電壓應在 **`epd_init` 執行後、送出 `PON` 時**量測。初始化未完成前
> PMIC 以 OTP 預設值運作，讀數不代表最終工作點 —— **此時量到的偏差值
> 未必是電路問題**。

# 十一、移植到自己的專案時

## 11.1 只需要三個檔案

`src/epd_el036.c`、`src/epd_el036.h`、以及 `main.c` 裡的 shell 指令（可不要）。
驅動本身不依賴本 app 的任何東西，只用到 `gpio_*` 與 `vTaskDelay`。

## 11.2 `.config` 兩個必要項目

```
CONFIG_PLATFORM_UART_BAUDRATE=921600   # 沒寫會被退回 115200
CONFIG_SHELL_EXEC_THREAD=y             # 沒開的話刷新期間 console 完全無回應
```

`CONFIG_PLATFORM_UART_BAUDRATE` 若不寫，**不會**套用 Kconfig 的預設值 ——
該符號不會出現在 `autoconf.h`，而是由 `bsp/common/platform_utils/platform_common.c`
的 `#ifndef` 硬退回 115200。boot2 仍用自己的傳輸率印出乾淨的開機訊息，
接著 app 把 UART 改掉，看起來就像「開機正常但 console 掛掉」。

整屏刷新需要數十秒。沒開 `CONFIG_SHELL_EXEC_THREAD` 的話指令是在 `shell_task`
內同步執行，整段期間 console 沒有回應，同樣容易誤判成當機。

## 11.3 建立任務要用靜態配置

```c
static StackType_t  app_stack[1024];
static StaticTask_t app_tcb;

xTaskCreateStatic(app_task, "epd_app", sizeof(app_stack) / sizeof(app_stack[0]),
                  NULL, 10, app_stack, &app_tcb);
```

在本 SDK 上，於 `vTaskStartScheduler()` **之前**呼叫動態的 `xTaskCreate()`
會讓 IPRO7 直接硬重置（非 CPU 例外、非看門狗；堆積本身正常，
`pvPortMalloc(4096)` 可成功）。SDK 內已驗證可運行的 app
（`ipro_ble_remote`、`ipro_lp_test`）全部使用 `xTaskCreateStatic`，
本包沿用相同做法。

## 11.4 移到 GPIO10-17 之後：換腳位時 SCL/SDA 不能亂選

目前預設接線集中在 GPIO10~17（客戶板實際使用的區塊）。CSB、DC、RST_N、
BUSY_N、PWR 是純 GPIO，換到任何空腳都可以；**SCL 與 SDA 不行** —— 兩者的
角色由腳位編號 modulo 4 決定（0=MISO、1=MOSI、2=SS、3=SCLK），與硬體 SPI
週邊直接綁定，PIO 引擎雖然沒有這個限制，但硬體 SPI 有。換腳位前先用這個
規則反推，不要憑感覺挑。

若之後改回使用 GPIO28-33（本包在內建 flash 組態下的原始配置），要注意這
六支腳同時是 SF3 外接 flash / SDH 的匯流排：若改用外接 flash
（`CONFIG_IPRO7_FLASH_2M/4M/8M`），這組腳會被 flash 控制器收回，面板需
改接其他空腳。
